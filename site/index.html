A shell that knows when to say no.

JevShell runs your commands like any Unix shell, grades every one of them against a deterministic safety policy first, and understands plain English when you'd rather not remember the flags.

The contract

The model classifies. It never executes.

Most AI shells ask a language model to write a command and then run the text it returns. JevShell does not have that code path. Jev answers a multiple-choice question with one of five operations; deterministic code turns that answer into an argument list.

No generated shell strings

Jev's reply is one of five enum members. Anything else raises before it reaches a command, so there is no path from model output to execution.

No shell=True, anywhere

Every process is an explicit Popen with its own argument list, stdin, stdout, cwd and environment. Three call sites, all intentional.

No AI in the safety decision

The policy engine is ordinary Python and never calls Jev. The model may propose an action; it cannot authorize one.

Policy

Every command gets a verdict first.

The policy reads the whole command tree, so a dangerous command cannot hide behind an alias, a variable, a pipe, a chain, a redirect or a background ampersand. Pick one and see what the engine returns.

rm -rf / BLOCK Refusing to delete the filesystem root.

A BLOCK is never offered a prompt. There is no answer that makes it run.

Natural language

Only when you're not writing a command.

Routing is deterministic and happens before any network call. A first word that is a builtin, an alias or something on your PATH is a command. A line containing a shell operator is a command. Only input that would otherwise fail with command not found reaches Jev, so typing ls never costs a round trip.

create a folder called reports→ mkdir reports
make an empty file called notes.txt→ touch notes.txt
show my current directory→ pwd
list the files here→ ls
delete notes.txt→ rm notes.txt  confirm
ai create a folder called src→ explicit prefix, always Jev

Targets come from a deterministic extractor, never from the model, and never from thin air. If a request names no path, the shell says so and waits rather than guessing. Set TYPESAFE_API_KEY to turn this on; without it every other feature works unchanged.

Limitations

What it doesn't do.

Worth knowing before you make it your login shell, which you shouldn't yet.

  • Safety is a guard rail, not a sandbox. Paths are checked before execution, so a path that changes in between defeats the check. The policy reads argument lists, so it cannot see what python script.py will do once it starts.
  • No command substitution. $(…) and backticks stay literal text and are never executed. That is deliberate, and tested.
  • No subshells, heredocs, brace or arithmetic expansion, and no 2> or 2>&1.
  • No job control. Background jobs are tracked but there is no fg, bg or Ctrl+Z.
  • No tab completion, no persistent history. History lives for the session.
  • Natural language covers five operations. It cannot express a pipeline or a redirect.
  • Confidence is not a sense check. It measures how cleanly the options separated, not whether the request was reasonable. Safety is what protects you.
